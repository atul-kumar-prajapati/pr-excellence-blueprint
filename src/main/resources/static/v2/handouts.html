Merge confidence

5 merge it · 4 nits · 3 some risk, you said so · 2 blocking · 1 split or rethink

Security, data, or a missing rollback: cap at 2. Claimed a test and did not show it: cap at 3. An agent can suggest a number. You own it.

Five rules

One purpose per PR.

No claim without evidence.

You own what you approve.

Keep it small enough to review.

Know who gets hurt if this is wrong.

Written template

Also in the repo at .github/pull_request_template.md

Self-review prompt

Review the diff between this branch and main as a strict senior reviewer.

For each finding give: file, severity (blocker / major / nit),
and who gets hurt if this ships.
Pay special attention to deleted lines. List any safeguard that was removed
(locks, ownership checks, idempotency keys, validation).
Then check the tests: for each test, say what behaviour it would catch if broken.
Flag tests that would pass even if the code were wrong.

Finish with a merge confidence score 1 to 5.
Any security, data, or rollback blocker caps the score at 2.
